argument-hint: <market> <interval> <candles> <analysisType> [dry-run|backtest|live] [momentum] [candlestick] [message] [keygen <KeyGen id>] [stop-to-entry XX YY] [trailing-stop XX YY] [add-to-position XX YY] [remove-from-position XX YY] [percent]
---

Load the `trade-bot-hyperliquid-perp` skill, then call `perp_trade_decision` once.

The plugin runs candlestick analysis and the other analysis types in its own library call. Do not call `analyze_candlestick_patterns` or any other `analyze_*` chart tool in this turn. Do not draw a chart from this result. A later message that asks for a chart still uses the interactive analysis tools.

- Market name: ${1:-}
- Candle interval: ${2:-4h}
- Number of candles: ${3:-200}
- Analysis type id: ${4:-}
- Remainder: ${@:5}

The market name is a Hyperliquid name such as `BTC`. If it is empty, stop and ask. If it is a contract address, stop and ask for the market name. Do not call `get_token_registry`. The name does not have to be a saved asset.

The analysis type must be one of the fifteen ids in the skill. If it is empty, stop and ask which id to use. Do not offer liquidity depth or a time-series analysis.

Before the call, read `/app/agent_llm_config/trade-desk.yaml` with the one grep in the skill. Pass the `universal` lines, the `keyLevels` lines, the `keyLevelFibonacci` lines, the `minConfidenceCandles` line, and the nine `classicPatterns` lines as `analysisSettings`. Those lines are the shared desk settings, the periods for each analysis type, the key-level touch and cluster settings, the Fibonacci bracket settings, the candlestick hit gate, and the classic-pattern scan settings. Do not pass the `keyLevels`, `keyLevelFibonacci`, `candlestick`, or `classicPatterns` headers, `version`, or `llmFallback` lines. Do not read `protocol-trade.yaml`. Do not cat the file and do not invent those numbers. Tell the user that editing `trade-desk.yaml` changes later runs. `minConfidenceCandles` applies to `candlestick_patterns` and to the `candlestick` switch. When that line is absent the plugin uses 0.8. `classicPatterns.minConfidence` stays the chart-pattern gate.

Read the remainder from the left.

- `stop-to-entry`, `trailing-stop`, `add-to-position`, and `remove-from-position` can all be present together. They are not alternatives. Each takes the next two numbers. Percents may include `%`. Pass every one that appears, on dry-run, backtest, and live, as `stopToEntry`, `trailingStop`, `addToPosition`, and `removeFromPosition`, for example `50 5`. Those numbers are not `percent`. Leave a rule off only when its words are absent. A backtest applies each passed rule to the paper position. For `trailing-stop`, the second percent must be below the first, so the trigger price stays ahead of the stop.
- A remaining number, or a number with `%`, is `percent`. Otherwise `percent` is 50.
- `backtest`, `dry-run`, and `live` choose `mode`. If none is present, use `dry-run`.
- The words `momentum`, `candlestick`, and `message` turn those switches on. Leave a switch off when its word is absent.
- `keygen` takes the next token, the KeyGen id. Pass it as `keygen`. That token is not `percent`. Omit `keygen` to use the preferred KeyGen for this chat. Do not pass an Ethereum address. When the result includes `keyGenId`, pass that id to every Hyperliquid build tool for this decision. When it is absent, those tools use the preferred KeyGen.
- When the word `message` is present, pass `message` true. On dry-run and live, at the start the plugin posts the KeyGen spot USDC still available and the unrealised PnL of open perpetuals. The first post opens one KeyGen thread. Later posts reply on that same thread. It sends that same text to Telegram when that webhook is configured. An open, a close, or a rule update on that run is a second reply on the same thread. That reply names the action and the price. Backtest does not post, even when the word is present. Do not call `send_keygen_message` or `send_telegram_message` for this text, and do not open another KeyGen thread. The plugin already posted it when the mode is not backtest.

Only `live` may be followed by a multi-sign request, and only when the tool returns an unsigned payload. An open or a close uses the existing order tools. `update-stop` uses `ctm_hyperliquid_build_update_position_tpsl_multisign` with `stopLossTriggerPxHuman` only. `add` uses `ctm_hyperliquid_build_limit_order_multisign` with the returned side, price, size, and `tif` `ioc`. `remove` uses `ctm_hyperliquid_build_close_multisign` with `isLong` and `szHuman`. When `decision` is `manage`, sign `actions` in order and wait until each request is broadcast before the next. Sign `add` and `remove` once per open position. If the result includes `accountMessage`, quote that text before the decision. Say it was posted on the plugin's one KeyGen thread. If the result includes `positionMessage`, quote that text too. It is the open, close, or rule update from this run, with the price, posted as a reply on that same thread. If `threadError` is set, quote it. If `telegramSent` is true, say the same text was sent to Telegram. If `telegramError` is set, quote that text. If `telegramSent` is false and `telegramError` is absent, do not say a Telegram message was sent. If the result includes `setupNotice`, quote that text in full before the decision. It starts with the node path `Node => AI Agent => Cron`. Do not leave that path out. If the result includes `userNotice`, tell the user that text, including the leverage and that they can ask to change it after USDC is on spot. Do not open an order and do not change leverage while that notice is present. Dry-run and backtest do not use real USDC. A result of do nothing is finished. Do not invent an order for it. On a backtest, report `skipped` with the ledger, including `candle` on each row, an `opened` row for each fill, and adjusted rows for `stop-to-entry`, `trailing-stop`, `add`, and `remove`. `candle` is 1-based. 1 is the oldest candle. If `analysisError` is set, quote that text. Use the `reasons` counts as the explanation. Do not invent another one.
