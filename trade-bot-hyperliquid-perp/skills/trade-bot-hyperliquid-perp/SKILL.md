# trade-bot-hyperliquid-perp

One tool, `perp_trade_decision`. **This plugin never signs and never posts a multi-sign request.** An open, a close, a stop move, an add, or a remove returns an unsigned payload. The agent opens the sign request.

Candlestick analysis, and every other accepted type, runs inside this plugin through the market-data library. That includes `analysisType` `candlestick_patterns` and the `candlestick` switch. Call only `perp_trade_decision` for this decision. Do not call `analyze_candlestick_patterns` or any other `analyze_*` chart tool in the same turn, and do not draw a candlestick menu from this result. The plugin returns the decision or the backtest numbers. A backtest includes `ledger`: an `opened` row when a position is filled, one row per closed trade, plus a final row when a position is still open. Each row has `candle`, `side`, `entryPrice`, `exitPrice`, `entryTimeMs`, `exitTimeMs`, `barsHeld`, `qty`, `margin`, `pnl`, `balanceUsdc`, and `reason` (`open`, `invalidation`, `target`, `liquidation`, `signal`, or `remove`). The fill is `status` `opened`, `reason` `open`, `barsHeld` 0, and `fillPrice` at the entry. A position rule adds a row with `status` `adjusted` and `reason` `stop-to-entry`, `trailing-stop`, `add`, or `remove`. `stop-to-entry` and `trailing-stop` include `stopPrice`. `add` and `remove` include `fillPrice`. A remove of the whole position is a closed row with `reason` `remove`. `candle` is the 1-based number of that row's candle in the window. 1 is the oldest candle. Report it with the row. `barsHeld` is the number of candles from the entry bar to the exit bar, or to the last bar when the position is still open. When `analysisType` is `candlestick_patterns`, or the `candlestick` switch confirmed the open, the row also has `candlestickPattern`, the pattern that opened the trade. A candlestick signal close also has `exitCandlestickPattern`. Report those names with the row. A `candlestick_patterns` open invalidates at the lowest low of the pattern candles for a long, and the highest high for a short. An engulfing, harami, piercing, or dark cloud cover uses the signal candle and the one before it. A morning star, evening star, three white soldiers, or three black crows uses the signal candle and the two before it. Any other pattern uses the signal candle. Liquidation stays the leverage price. The closer of the invalidation and the liquidation is the exit. A backtest also includes `skipped`. `skipped.bars` is the number of walked candles. `skipped.reasons` counts why a flat bar did not open: the library unclear reason, or `Clear idea, entry not inside the bar.` `skipped.analysisErrors` counts flat bars whose analysis failed, and `skipped.analysisError` is the first failure text. Report `skipped` with the ledger. If `analysisError` is set, quote that text. Use the `reasons` counts as the explanation. Do not invent another one. It does not return a chart highlight.

Interactive chart analysis stays available. A later message that asks for a chart, or that names an `analyze_` tool, uses those chart tools as usual.

## Arguments

- `asset` is the Hyperliquid market name, such as `BTC`. A `0x` contract address is an error. The name does not have to be a saved token on this node.
- `interval` and `candleCount` select the Hyperliquid candles. `lookbackDays` is optional.
- `analysisType` is one of these library ids, written with underscores: `trend_structure`, `elliott_waves`, `key_levels`, `key_level_fibonacci`, `divergence`, `range_volatility`, `bollinger_bands`, `donchian_breakout`, `supertrend`, `ichimoku`, `z_score`, `moving_averages`, `chart_patterns`, `momentum`, `candlestick_patterns`. Liquidity depth and the time-series analyses are not accepted, because they do not produce a Trade Idea.
- `analysisSettings` is the shared desk settings, the periods for that analysis type, and the classic-pattern scan settings. The shared settings and periods are the `universal` lines in `/app/agent_llm_config/trade-desk.yaml`. The key-level settings are the lines under `keyLevels` in that same file: `tolerancePct`, `swingLookback`, `minTouches`. The Fibonacci settings are the lines under `keyLevelFibonacci`: `minTouches`, `retracementRatio`. The scan settings are the lines under `classicPatterns`: `minConfidence`, `smoothHeadShoulders`, `smoothWindow`, `retestTolerancePct`, `retestAtrPeriod`, `retestAtrMultiplier`, `entryMode`, `insideEntry`, `breakTolerancePct`. The candlestick hit gate is the `candlestick` line `minConfidenceCandles`. `classicPatterns.minConfidence` stays the chart-pattern gate. Read them with one command: `grep -E '^[ \t]*[A-Za-z][A-Za-z0-9]*:' /app/agent_llm_config/trade-desk.yaml`. Pass the `universal` lines, the `keyLevels` lines, the `keyLevelFibonacci` lines, the `minConfidenceCandles` line, and those nine `classicPatterns` lines. Do not pass the `keyLevels`, `keyLevelFibonacci`, `candlestick`, or `classicPatterns` headers, `version`, or `llmFallback` lines. Do not read `protocol-trade.yaml`. Position size comes from `percent`, not from venue sizing. Do not cat the file, do not page an offload, and do not glob for it. The comments are for the editor, and `agent_read_file` cannot open that path. Omit a key the grep does not print. Do not invent numbers. Editing that file changes later runs. The plugin does not read the file.
- `mode` is `dry-run`, `backtest`, or `live`. Only `live` reads the KeyGen spot USDC balance and the open perpetual. On a live result, tell the user the KeyGen leverage for that market. If `keyGenId` is set, that is the KeyGen for this run. Pass it to every Hyperliquid build tool. If it is absent, those tools use the preferred KeyGen. If `setupNotice` is set, quote that text in full. It starts with the node path `Node => AI Agent => Cron`. Do not leave that path out. The plugin checks only this node's `auto-sign-and-broadcast` job. The notice still tells the user to set `auto-accept-sign-request` on the other nodes. If `userNotice` is set, say that text. The KeyGen spot USDC balance is empty, so do not open an order and do not change leverage. Hyperliquid accepts a leverage change only after USDC is on spot. After the user has sent that USDC, they can ask to change the leverage.
- `message` is an optional switch. It defaults off. When it is on, and `mode` is not `backtest`, the plugin reads the selected KeyGen before the analysis. Omit `keygen` and that is the preferred KeyGen for this chat. It posts `accountMessage` with `sendKeyGenMessage`. The body is the spot USDC still available and the unrealised PnL of open perpetuals, summed from each position. A flat book is `0.00`. The first post for that KeyGen address opens one thread. Its title is `Hyperliquid account`. Later posts are replies to that root message and have no title, so they stay on the same thread. The root id is kept in `.position-state.json` on this node. `keyGenThreadId` is that root. `keyGenMessageId` is the account note from this run. If the root was deleted, the next post opens a new thread. The same body is sent with `sendTelegram` when a Telegram webhook is configured. Backtest does not read that balance and does not post, even when `message` is on. The plugin does that send on dry-run and live. On that same run, an open, a close, or a rule update is a second reply on that thread. The body is `positionMessage`. An open or a close names the side, the market, and the price. Stop-to-entry and trailing-stop name that rule and the new stop. An add or a remove names the side, the market, and the price. Several actions are one reply, one line each. `positionMessageId` is that reply. Quote `positionMessage` with the decision. Backtest does not post it. Do not call `send_keygen_message` or `send_telegram_message` for this text. Do not open a second KeyGen thread for it. If `accountMessage` is set, quote it and say it was posted on the plugin's KeyGen thread. If `telegramSent` is true, say the same text was sent to Telegram. If `telegramError` is set, quote it. If `threadError` is set, quote it. If `telegramSent` is false and `telegramError` is absent, the webhook is not configured. Do not say a Telegram message was sent. On backtest those fields are absent. Do not say a message was posted. A failed KeyGen post is an error. Quote it and stop. Do not open an order for that error.
- `keygen` is optional. Omit it to use the preferred KeyGen for this chat. A value is a KeyGen id, not an Ethereum address. Leverage, the live spot balance, the open perpetual, and KeyGen notes use that KeyGen. When the result includes `keyGenId`, pass it to every Hyperliquid build tool.
- `momentum` and `candlestick` are optional switches. Both default off. When `momentum` is on, an open requires the momentum Trade Idea on that same side and clear (RSI oversold with a bullish MACD cross, or RSI overbought with a bearish MACD cross). When `candlestick` is on, an open requires the candlestick Trade Idea on that same side and clear, buy for a long and sell for a short, using `minConfidenceCandles`. A close does not use either switch. If the primary type is already momentum or candlestick, that idea is its own confirmation.
- `percent` is the fraction of the notional Hyperliquid will allow. The default is 50. Opening margin is notional divided by leverage, and collateral left over must cover 10% of that notional, so the maximum notional is `account * leverage / (1 + 0.1 * leverage)`. `percent` takes that fraction. Live uses the KeyGen perp account value. Dry-run and backtest use the paper balance.
- `stopToEntry`, `addToPosition`, `removeFromPosition`, and `trailingStop` are optional and can be passed together. Each is two percents, such as `50 5` or `50% 5%`. The first percent is how far the previous candle close must travel from the entry toward the target. The second percent is what the rule does. Omit a rule to leave it off. All four need a target on the open position. A backtest keeps the target from the entry idea and applies every rule that was passed, including on a paper position. `stop-to-entry`, `add-to-position`, and `remove-from-position` run once. The trailing stop updates again whenever a new previous close is still that far toward the target and the new stop is tighter. For `trailing-stop`, the second percent must be below the first, so the trigger price stays ahead of the stop. Live uses the resting take-profit, or the current idea's target when that order is absent.
- `stop-to-entry 50 5` moves the stop once. With entry 10 and target 20, a previous close of 15 or higher moves a long stop to `10 + 5% × (20 − 10) = 10.5`. A short uses the same fraction toward its target, so entry 20 and target 10 move the stop to 19.5. The offset percent must be below the progress percent. The stop only tightens. The fill stop becomes that price. Pass the returned `stopLossTriggerPxHuman` to `ctm_hyperliquid_build_update_position_tpsl_multisign`. Leave the target argument off so the resting target stays. This tool does not use gas. After the new stop is resting, a later call does not return this action again.
- `add-to-position 50 25` adds once. The added margin is 25% of the collateral still free under the same notional cap. The backtest fills that add at the next bar's open. Live returns an unsigned IoC limit at the latest close, in the position's direction, via `ctm_hyperliquid_build_limit_order_multisign` (`isBuy` true for a long, `tif` `ioc`). Sign an add once for that open position. A later call can return it again while the previous close stays beyond the level.
- `remove-from-position 75 50` closes 50% of the current position once, at the same trigger. A backtest fills the reduction at the next bar's open and realizes that slice. Live returns an unsigned reduce via `ctm_hyperliquid_build_close_multisign` with `isLong` and the returned `szHuman`. `100` closes the whole position. Sign a remove once for that open position.
- `trailing-stop 50 5` sets the stop back from the previous close by 5% of the entry-to-target range, once that close has moved 50% of the way. The offset percent must be below the progress percent, so the trigger price stays ahead of the stop. Entry 10 and target 20 with a close of 15 put a long stop at `15 − 5% × (20 − 10) = 14.5`. A later close of 16 moves it to 15.5. A short puts the stop above the close by that same amount, so entry 20, target 10, and close 15 put the stop at 15.5. The stop only tightens. The backtest uses that price as the fill stop and writes a `trailing-stop` row each time it moves. Live returns one `update-stop` at the new price for `ctm_hyperliquid_build_update_position_tpsl_multisign`. A later call returns a new price when the previous close has moved the trail further. If `stop-to-entry` is also due, the returned stop is the tighter of the two.

## Decision

| Situation | Result |
|---|---|
| No open perpetual, and a clear idea, and momentum confirms when it is on, and candlestick confirms when it is on | unsigned payload that opens |
| Open perpetual in the opposite direction | unsigned payload that closes |
| Open perpetual, and the previous close has reached a stop, trail, add, or remove level | unsigned `update-stop`, `add`, or `remove`. A trail returns `update-stop` again when the close moves it tighter. Several due rules return `decision` `manage` and `actions` in that order |
| Open perpetual already in that direction, and no rule is due | do nothing |
| No clear idea, or momentum or candlestick is on and does not confirm an open | do nothing |

An opposite clear idea closes the position and does not also move the stop or change the size. When `actions` has more than one entry, sign them in order and wait until each request is broadcast before the next. The plugin still does not sign.

Dry-run treats the book as flat and does not read a balance. Every mode reads the KeyGen's current Hyperliquid leverage for that market once, at the start, and sizes an open with the collateral rule above. A paper open fills at the Trade Idea entry price only on a candle whose low and high contain that price. The entry can be on the signal candle or a later one while the idea is still an open. On a later bar, a position rule looks at the previous close before the exit check. A stop move applies to that bar. An add or a remove fills at that bar's open. A later backtest bar that trades through the idea's invalidation, its target, or the liquidation price closes the paper position at that price. The book is then flat, so a clear idea can open again, including on that same bar. Dry-run and backtest do not use real USDC, and a backtest close does not sign or post a wallet transaction.
